# Local AI toolkit: full audit (2026-10-06)

Six independent read-only reviews, each one area, all against `main` at 3a4668a: security and privacy,
long-term reliability, the update from the owner's old install, test gaps, code structure, and day-to-day
usefulness. The key claims were re-checked against the code (and Open WebUI 0.11.4's own source) before
they were listed here. Items already fixed in `IMPROVEMENTS.md` #1-#76 are not repeated.

**Severity** is for this setup: one home PC, one owner. **Effort**: S = under an hour, M = under a day,
L = more. IDs are referenced from `IMPROVEMENTS.md`.

## Bottom line

The toolkit is strong where it has been tested hardest: data safety (atomic state, verified backups,
restore with rollback), non-elevated scheduled tasks, loopback-only ports, and clear error messages. Its
weak spots are:

1. **The coming update from the owner's old install** can stop half-way (U1). Some of what it changes
   also hasn't been announced or made reversible (U2-U4).
2. **Prompt injection.** A web page or document can steer an uncensored model into reading past chats
   and sending them out in a URL (S1). Any page on `localhost` can also call Open WebUI with the
   owner's login (S2).
3. **Silent failure over months.** Alerts can stop reaching the owner without anyone noticing (R1),
   search quietly degrades (R5), and a GPU spill or a driver change goes unseen (R6).
4. **Tests that never touch the real thing.** The real Docker stack and the end-to-end flows on
   Windows PowerShell 5.1 never run in CI (T1, T2).
5. **Document search barely works.** Its embedding model reads about the first 256 tokens of each
   2,000-token chunk (C1).
6. **Releases.** "Update toolkit" installs whatever is on `main`, with no version tag (S3/M1).

## Where the reviews were overruled

- **Code execution (C10):** a reviewer suggested turning on in-browser Python. Kept as opt-in only, given S1/S2.
- **Memory (S4):** dropping automatic memory would remove a feature the owner asked for; reviewing new
  memories was chosen instead.
- **Hiding presets (C2):** waits for the owner's measured speeds rather than guessing.
- **"WIP commits reached main":** checked against main's push history. Main's tip never pointed at them;
  they were stepping stones on the working branch. The release-tag fix (S3) still stands, because this
  rests on process alone.

## Owner checklist for the coming update

0. Best: wait until Phase A has landed on `main` (this audit's IMPROVEMENTS entry says when). U1 in particular
   can stop the update half-way if ComfyUI is open.
1. Before: close ComfyUI and games; set Windows sleep to Never for the evening; check that ~57 GB is free
   on the models drive (or plan to skip the official models); copy the newest archive in `C:\AI\Backups`
   to another drive.
2. Run the one-line command from the README's "Run it" section in PowerShell. The old install has no
   Start-menu shortcut yet. Approve the UAC prompt and leave the window open (1-3 hours).
3. If it stops (busy GPU, Wi-Fi, sleep), run the same command again. Downloads resume and finished stages
   are skipped.
4. After: a Start menu > Local AI folder appears. Run Health check, and send the install report
   (`C:\AI\install-report.md`) back for the speeds of the new models.
